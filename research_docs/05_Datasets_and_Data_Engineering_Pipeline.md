## 2. In-Depth Dataset Schemas & Ground-Truth Mechanics

### 2.1 Synthetic Ground-Truth Suites (S1, S2, S3, S1c, S2c)
The synthetic suites are programmatically generated by `data.make_synthetic()` using fixed random seeds. In all five suites:
- Input features $x_0, x_1, \dots, x_9$ are drawn independently from $\text{Uniform}(0, 1)^d$ ($d = 10$).
- **Ground-Truth Relevance Invariant:** Only the first three features ($x_0, x_1, x_2$) determine the binary class label $y \in \{0, 1\}$. Features $x_3, \dots, x_9$ are completely uninformative random noise.
- **Decision Rules:**
  - **S1 (Additive Non-linear):** $y = 1 \iff x_0^2 + x_1^2 + x_2^2 \ge 0.75$.
  - **S2 (Multiplicative Interaction):** $y = 1 \iff x_0 \cdot x_1 + x_1 \cdot x_2 + x_0 \cdot x_2 \ge 0.75$.
  - **S3 (Conjunctive Boolean AND):** $y = 1 \iff (x_0 \ge 0.5) \land (x_1 \ge 0.5) \land (x_2 \ge 0.5)$.
- **Correlated Extensions (S1c, S2c):** Designed for pre-registered RQ1 extension B3. Feature $x_3$ (normally uninformative noise) is transformed into a noisy copy of informative feature $x_0$:
  $$x_3 = \text{clip}\big(x_0 + \mathcal{N}(0, 0.05^2), \, 0.0, \, 1.0\big)$$
  This tests whether conditional explainers (`PaceShap(sigma=0.1)`) correctly allocate credit to correlated proxies without manifold distortion.

### 2.2 Deduplication Audit: The Skin Segmentation Dataset (Run P3)
* **The Anomaly:** The raw UCI Skin dataset (`Skin_NonSkin.txt`) contains $245,057$ samples of 3 RGB color values ($B, G, R \in [0, 255]$).
* **Audit Findings:** A systematic hash check revealed that **$79.01\%$ of rows are exact duplicates** of other rows in the dataset ($193,613$ duplicate rows). However, zero color coordinates appear with conflicting class labels (no label noise).
* **The Deduplicated Variant:** `data.dedup()` strips exact coordinate duplicates while verifying label consistency, yielding **$51,444$ unique instances**.
* **Empirical Verification (Run P3):** Pre-registered experiment P3 ran CFMNN and Self-Repair on both raw and deduplicated variants across seeds 260–269. Self-repair raised macro-F1 by $+6.20$ points on deduplicated Skin (matching the $+5.72$ points on raw Skin), proving that CFMNN's empirical repair gains are not an artifact of duplicated samples.

### 2.3 The Sepsis Pathology Audit: Why Sepsis Was Excluded
The PReMI 2023 paper evaluated CFMNN on Sepsis survival. However, our codebase audit revealed why Sepsis is mathematically pathological:
1. Sepsis has only 3 discrete features: Age (years), Sex ($0/1$), and Episode number.
2. Across $110,204$ rows, there are only **$975$ distinct coordinate combinations**.
3. **$91.5\%$ of instances share identical feature coordinates with patients of the opposite outcome** (one patient lived, one died, with identical age, sex, and episode).
4. An optimal Bayes classifier that assigns the majority outcome to each of the 975 unique coordinate buckets achieves a ceiling accuracy of **$92.65\%$**, which is virtually identical to the trivial zero-information baseline of always predicting "alive" ($92.65\%$).
5. In G0 benchmark runs, our single CFMNN scored $48.65\%$, and the original paper's MapReduce ensemble scored $68.76\%$ (both far below the trivial $92.65\%$ majority class predictor). Sepsis was therefore formally excluded from all benchmark evaluations, as documented in `data/README.md`.

## 3. Data Engineering & Leakage Prevention Pipeline

Data splitting, scaling, and batch ingestion are implemented in `pace_cfmnn/data.py` with zero data leakage guarantees:

```
+----------------------------------------------------------------------------------------------------+
|                                    DATA PREPROCESSING PIPELINE                                     |
|                                                                                                    |
|    [ Raw Ingested Dataset (X, y) ]                                                                 |
|                 |                                                                                  |
|                 v                                                                                  |
|    [ Stratified 80/20 Train/Test Split ] (data.paper_split, Seed S)                                |
|                 |                                                                                  |
|                 +-----------------------------------+                                              |
|                 |                                   |                                              |
|                 v                                   v                                              |
|        [ Training Split: 80% ]             [ Test Split: 20% ]                                     |
|                 |                                   |                                              |
|                 v                                   | (No test stats leaked!)                      |
|        Fit Min-Max Scaler                           |                                              |
|        min_j = min(X_train[:, j])                   |                                              |
|        max_j = max(X_train[:, j])                   |                                              |
|                 |                                   |                                              |
|                 v                                   v                                              |
|        Apply Scaler to Train:              Apply Scaler to Test:                                   |
|        X_train in [0, 1]^(N_train x d)     X_test in [0, 1]^(N_test x d)                           |
+----------------------------------------------------------------------------------------------------+
```

### Preprocessing Specifications
1. **Partition Protocol (`data.paper_split`):** Uses scikit-learn's `StratifiedShuffleSplit(n_splits=1, test_size=0.20, random_state=seed)`. For fixed pre-split UCI benchmarks (Thyroid, Shuttle, Landsat), the official training and testing partitions are loaded directly.
2. **Min-Max Scaling (`data.fit_scaler`):**
   $$X_{ij} \leftarrow \frac{X_{ij} - \min(X_{\text{train}, \cdot, j})}{\max(X_{\text{train}, \cdot, j}) - \min(X_{\text{train}, \cdot, j}) + 10^{-12}}$$
   If a feature has zero variance in the training split ($\max = \min$), its scaled values are clamped to $0.5$. Test features that exceed the training envelope are clipped to $[0.0, 1.0]$.
3. **Explainer Background Isolation:** In pre-registered benchmark v3 (`results/faithfulness_v3/`), PACE-SHAP and KernelSHAP select background rows strictly from an explainer-dedicated partition of $200$ training instances, while deletion/insertion tests evaluate on a separate, disjoint set of $200$ instances. No explainer is ever evaluated on background instances it has observed.
